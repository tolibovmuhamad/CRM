## Окружение

Windows, терминал **Git Bash (MINGW64)** внутри VS Code. Работает обычный `curl` и `source` — `curl.exe` и PowerShell-синтаксис не нужны.

Файлы сохранять с переводом строки **LF**, не CRLF. Особенно `.env`: при CRLF в переменную попадёт невидимый `\r`, заголовок уйдёт как `X-Figma-Token: figd_xxx\r`, и Figma вернёт 403 без внятной причины. Починка: `sed -i 's/\r$//' .env`.

## Доступ к Figma

Только REST API. Аккаунт на плане **Free** — плагин Figma MCP требует Dev/Full seat и вернёт 403, не пытаться его настраивать.

Доступы в `.env` (в git не попадает). Токен **никогда** не писать в код, коммиты, документы и этот файл. `FIGMA_FILE_KEY` и `FIGMA_NODE_ID` секретами не являются:

```
FIGMA_FILE_KEY=wElKcFwqxmtHQdtUlDvmY0
FIGMA_NODE_ID=10588:38828
```

**Каждый вызов bash — новая сессия, переменные не переживают между командами.** Поэтому `source .env` идёт в той же команде, через `&&`:

```bash
# Проверка доступа — начинать с неё, если что-то не работает
source .env && curl -s -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/files/$FIGMA_FILE_KEY?depth=1" | head -c 300

# Страницы и верхнеуровневые фреймы
source .env && curl -s -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/files/$FIGMA_FILE_KEY?depth=2" -o figma/pages.json

# Полное дерево конкретного экрана
source .env && curl -s -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/files/$FIGMA_FILE_KEY/nodes?ids=$FIGMA_NODE_ID" -o figma/node.json

# Библиотека стилей: палитра и типографика
source .env && curl -s -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/files/$FIGMA_FILE_KEY/styles" -o figma/styles.json

# Рендер экрана в PNG — вернёт временную ссылку
source .env && curl -s -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/images/$FIGMA_FILE_KEY?ids=$FIGMA_NODE_ID&format=png&scale=2"

# Экспорт иконок в SVG — тот же эндпоинт, format=svg, ids через запятую
```

Ответы писать в `figma/` — это кэш выгрузки, не исходники, в git не попадает. Выгрузку не повторять без нужды: если файл в `figma/` уже есть и свежий, читать его.

**Токен на 7 дней, истекает 27.07.2026, scope `file_content:read`.** Получил 403 — не гадать: сначала прогнать проверку доступа выше. Если она тоже 403, токен истёк или отозван, сказать заказчику — он выпустит новый и заменит одну строку в `.env`. Самому токены не генерировать и не просить прислать в чат.

## Архитектура

Слоистость Feature-Sliced в `src/`, импорты идут **строго сверху вниз** — обратные импорты запрещены:

```
pages → widgets → features → entities → shared
```

- `app/` входная точка, роутер, провайдеры · `pages/` один экран на роут · `widgets/` крупные составные блоки (`sidebar`, `topbar`, `bottom-nav`) · `features/` действия/UI-состояние (`theme`, `language-switcher`, `sidebar`) · `entities/` предметные сущности (`student`…) · `shared/` (`ui/` компоненты + `icons`, `api/`, `lib/`, `config/`, `i18n/`, `styles/`) · `mocks/` фикстуры.

**UI и каркас (этапы 3–4):** базовые компоненты — в `shared/ui` (barrel `@/shared/ui`), стили на токенах через Tailwind, состояния и a11y по UI-Kit; `Modal`/`Drawer` используют `shared/ui/lib/dialog` (ловушка фокуса, Esc). Каркас страницы — `RootLayout` (Sidebar + Topbar + BottomNav). Навигация — `shared/config/navigation`. Классы склеивать через `cn` (`shared/lib/cn`).

### Слой данных (ТЗ §6) — ключевая абстракция

Все запросы идут через один интерфейс `CrmApi` с двумя реализациями, переключение переменной окружения, **без правок в компонентах**:

```ts
// дефолт — mock: любое значение кроме 'http' даёт моки
export const api: CrmApi =
  import.meta.env.VITE_API_MODE === 'http' ? httpApi : mockApi;
```

- Компоненты не знают, откуда пришли данные.
- Моки отдают ответ с задержкой **200–600 мс** и умеют возвращать ошибку — иначе состояния загрузки и ошибки не проверить.
- Каждый ответ бэкенда проходит через **Zod-схему**, схема — единственный источник типов, руками типы не дублировать.
- Пагинация, сортировка, фильтры заложены в сигнатуры сразу, даже если в моках список короткий.

**Как это реализовано (этап 2):**
- Схемы и типы сущностей — в `src/shared/api/schemas/` (а **не** в `entities/`). Причина: `CrmApi` живёт в `shared` (ТЗ §6), а `shared` по правилу слоёв не может импортировать из `entities`. Поэтому контракт данных целиком в `shared/api`; слой `entities/<name>` **потребляет** эти типы и держит хуки/UI сущности (пример — `entities/student`).
- Переключатель — `shared/api/index.ts` (`VITE_API_MODE`, сейчас реально работает только `mock`; `http` — заготовка, бросает 501).
- Мок: `shared/api/mock/` — `mockApi` + генерик `queryList` (фильтр→поиск→сортировка→пагинация) + `latency` (`mockConfig`: `minDelayMs`/`maxDelayMs`/`errorRate`). Чтобы вручную проверить ошибку — `mockConfig.errorRate = 1` в консоли; в тестах задержку глушить.
- Фикстуры — `src/mocks/fixtures/*`, прогоняются через схемы при загрузке (`shared/api/mock/db.ts`).
- Хуки — TanStack Query в `entities/<name>/api`, ключи — `shared/api/queryKeys.ts`.
- **Деньги — в дирамах** (целые), формат через `shared/lib/money`.

## Конвенции кода (ТЗ §9)

- Компонент = папка: `Button/Button.tsx`, `Button.module.css`, `index.ts`.
- Функциональные компоненты; `React.FC` **не** использовать; пропсы типизировать явно.
- `any` запрещён — писать `unknown` и сузить.
- Магических чисел и хардкодных цветов в компонентах нет — всё из токенов.
- Названия компонентов и пропсов — из Figma (в Figma `StudentCard` → в коде `StudentCard`).
- **Деньги — целые в дирамах** (1 сомони = 100 дирам), не `float`. Хранение/моки/схемы/расчёты в дирамах, вывод в сомони — через хелпер `shared/lib/money`. Касается Payments, Debtors, Salary, Avans, контрактов, дохода групп.
- Одна ответственность на компонент; больше 150 строк — повод разбить.
- Коммиты по Conventional Commits (`feat:`, `fix:`, `refactor:`).
- **Доступность обязательна**: интерактивные элементы доступны с клавиатуры, фокус видимый; `aria-label` на иконочных кнопках; контраст текста ≥ 4.5:1 (если в макете ниже — сообщить заказчику, не молчать); модалки ловят фокус, закрываются по Esc, возвращают фокус на триггер.
- Текст в интерфейсе (ТЗ §10): кнопка называет действие; действие сохраняет имя на всём пути («Сохранить» → «Сохранено»); ошибка объясняет, что случилось и что делать; пустой экран приглашает к действию; термины предметные, не системные.

## Когда неясно — спросить

Макет неоднозначен, поля в форме не читаются, состояние экрана не нарисовано, два компонента выглядят одинаково но названы по-разному — **спросить заказчика, а не додумать**. Придуманное поле или выдуманное состояние дороже одного вопроса. Так же с полями модели: которых нет в макете — не изобретать; которые есть, но не описаны в ТЗ §7 — добавить и сказать об этом.

## Готовность экрана (ТЗ §11)

Вёрстка совпадает с макетом (отступы/размеры/цвета/шрифты из токенов) · работают все состояния (загрузка, пусто, ошибка, много данных) · адаптив 360–1920 px по мобильному макету · клавиатурная навигация проходит весь экран · формы валидируются через Zod, ошибки рядом с полем · `npm run lint` и `npm run typecheck` без ошибок · тесты на бизнес-логику и нетривиальные компоненты.

## Команды

`npm install` — зависимости. `npm run dev` — дев-сервер (Vite, порт 5173). `npm run build` — `tsc -b` + прод-сборка. `npm run typecheck` — `tsc -b`. `npm run lint` — ESLint. `npm run format` — Prettier. `npm test` — Vitest (watch), `npm run test:run` — однократно; один файл: `npm run test:run -- src/shared/lib/money.test.ts`.

**Заметки по окружению:**
- `.tsbuildinfo` от `tsc -b` кэшируется; при странных ошибках типов — удалить `*.tsbuildinfo`.
- Vitest держать в мажоре, совместимом с Vite (сейчас Vitest 3 + Vite 6, одна копия vite — `npm ls vite` для проверки; дубль ломает типы `vite.config.ts`).
- **Правки в файлах делать инструментами (Write/Edit), не через Bash-запись — Bash-правки в исходниках откатываются хуком.**
- Неразрывный пробел в строках вывода разрешён (правило `no-irregular-whitespace` со `skipTemplates`); между токенами кода — ошибка.
