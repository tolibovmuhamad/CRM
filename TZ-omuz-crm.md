## 1. Проект

**CRM учебного центра «Omuz».** Не sales-CRM: домен — обучение. Студенты, группы, курсы, менторы и сотрудники, журнал успеваемости и посещаемости, платежи и бухгалтерия, зарплата менторов, выпускники и трудоустройство, SMS-рассылки, администрирование. Валюта — сомони (Таджикистан). В макете десктоп (1440) и мобайл (360) — обе версии в объёме.

Задача первого этапа: собрать фронтенд, точно повторяющий макет, на данных-заглушках, с подготовленным местом для подключения реального API.

Полный список экранов — в `docs/screens.md`, компоненты — в `docs/components.md`, порядок работ — в `roadmap.md`. ТЗ задаёт архитектуру и правила, макет задаёт содержание.

## 2. Стек **[решено]**

| Слой | Выбор |
|---|---|
| Язык | TypeScript, `strict: true` |
| Фреймворк | React 18 |
| Сборка | Vite |
| Роутинг | React Router |
| Серверное состояние | TanStack Query |
| Клиентское состояние | Zustand — только фильтры, модалки, UI |
| Формы | React Hook Form + Zod |
| Даты | date-fns |
| Тесты | Vitest + Testing Library |
| Линт | ESLint + Prettier |
| Графики | Recharts |
| Локализация | i18next + react-i18next |

**Графики [решено]:** дашборд использует линейные, area-, пончиковые и столбчатые диаграммы (Leads, Attendance, Income, Enroll, Left courses). Кастомной сложной графики нет → **Recharts**. Палитра серий — `chart` в `src/shared/styles/tokens.ts`.

**Стилизация [решено]: Tailwind.** Макет на сетке 4px, шкала отступов и радиусов регулярная, богатый набор переиспользуемых компонентов с матрицей состояний (см. `docs/components.md`) — это профиль Tailwind, не CSS Modules. Токены из `src/shared/styles/tokens.ts` завести в `tailwind.config` (палитра, типографика, spacing, radius, shadow). Произвольные значения (`w-[137px]`) — только как исключение, обычные шаги — из шкалы. Не смешивать с CSS Modules.

**Локализация [решено]:** интерфейс трёхъязычный — русский, таджикский, английский (переключатель в шапке). i18n закладывается с самого начала: тексты через ключи, без строк в компонентах. Язык по умолчанию и формат дат/чисел/валюты (сомони) — уточнить у заказчика.

## 3. Доступ к Figma

### Переменные окружения

Файл `.env` в корне проекта. **`.env` в git не попадает.**

```
FIGMA_TOKEN=<personal access token, scope file_content:read>
FIGMA_FILE_KEY=wElKcFwqxmtHQdtUlDvmY0
FIGMA_NODE_ID=10588:38828
```

Первым делом, до создания `.env`:

```bash
echo ".env" >> .gitignore
```

Токен в этом документе, в коде, в коммитах и в переписке не появляется — только в `.env`.
Ключ файла и node-id секретами не являются, их можно писать открыто.

### Эндпоинты

```bash
source .env

# Страницы файла и верхнеуровневые фреймы — обзор объёма
curl -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/files/$FIGMA_FILE_KEY?depth=2" -o figma/pages.json

# Полное дерево конкретного экрана
curl -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/files/$FIGMA_FILE_KEY/nodes?ids=$FIGMA_NODE_ID" -o figma/node.json

# Библиотека стилей: палитра и типографика
curl -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/files/$FIGMA_FILE_KEY/styles" -o figma/styles.json

# Рендер экрана в PNG — вернёт временную ссылку на картинку
curl -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/images/$FIGMA_FILE_KEY?ids=$FIGMA_NODE_ID&format=png&scale=2"
```

Папку `figma/` добавить в `.gitignore` — это кэш выгрузки, не исходники.

**Ограничение:** аккаунт на плане Free. MCP-плагин Figma требует Dev или Full seat и вернёт 403 — работаем через REST API.

Процедура этапа (для истории):

1. Выгрузить `pages.json`, `styles.json`, `node.json` по командам выше

3. Из `styles.json` и узлов собрать `src/shared/styles/tokens.ts`:

   - типографика — семейство, размер, начертание, межстрочный, трекинг для каждой роли
   - шкала отступов — проверить, кратна ли 4 или 8
   - радиусы, тени, границы
4. Составить `docs/screens.md` — экран, его назначение, состояния (загрузка, пусто, ошибка), если они есть в макете
5. Составить `docs/components.md` — переиспользуемые компоненты с вариантами и состояниями (default / hover / active / disabled / focus)
6. **Обновить это ТЗ:** заменить все пункты **[по макету]** фактами, снять метки
7. Показать заказчику список экранов и предложенный порядок работ. Дождаться подтверждения

## 5. Структура проекта

```
src/
  app/              # входная точка, роутер, провайдеры
  pages/            # экраны, один на роут
  widgets/          # крупные составные блоки: сайдбар, шапка, таблица студентов
```

## 6. Слой данных

Реальный бэкенд пока не подключаем — только моки (§12.1), поэтому фронтенд не должен зависеть от будущего API.

Все запросы идут через интерфейс, у которого сейчас одна реализация — мок, позже вторая — HTTP. Переключение переменной окружения, без правок в компонентах.

```ts
// shared/api/types.ts
export interface CrmApi {
  getStudents(params: StudentsQuery): Promise<Paginated<Student>>;
  getStudent(id: string): Promise<Student>;
  createStudent(dto: CreateStudentDto): Promise<Student>;
  getGroups(params: GroupsQuery): Promise<Paginated<Group>>;
  markAttendance(lessonId: string, dto: AttendanceDto): Promise<Lesson>;
  getPayments(params: PaymentsQuery): Promise<Paginated<Payment>>;
  // ...
}

// shared/api/index.ts
export const api: CrmApi =
  import.meta.env.VITE_API_MODE === 'mock' ? mockApi : httpApi;
```

Требования:

- Компоненты не знают, откуда пришли данные
- Моки отдают ответ с задержкой 200–600 мс и умеют возвращать ошибку — иначе состояния загрузки и ошибки не проверить
- Каждый ответ бэкенда проходит через Zod-схему. Схема — единственный источник типов, руками типы не дублировать
- Пагинация, сортировка, фильтры заложены в сигнатуры сразу, даже если в моках список короткий

## 7. Модель данных

Домен — учебный центр (первая гипотеза про Client/Deal/Stage оказалась неверной и заменена). Сущности выведены из экранов и форм макета. Точные поля — из карточек и форм при реализации раздела; ниже опорный набор.

- **Student** — id, ФИО, телефоны (свой и родителя — в макете поповер Student/Father), группы, курс, статус (active / no active / finished), наличие аккаунта, контракт (см. Contract), дата поступления, аватар, отметка «премиум» (корона в списке)
- **Contract** — id, studentId, статус (active / N дней осталось / finished), срок, сумма, файл
- **Group** — id, название (напр. «C# 5 June»), курс, ментор, филиал, расписание, список студентов, доход, счётчики absent/late
- **Course** — id, название (C#, C++, Frontend, Python, HTML & CSS, UX/UI…), теги, ресурсы (файлы: pdf/doc/ppt/image/video), клиенты/студенты
- **Employee / Mentor** — id, ФИО, должность (Admin/Manager/Mentor/Developer), уровень ментора (Level → ставка), группы, материалы, зарплата
- **Lesson / Attendance** — привязка к группе и дате, тип (Lecture/Practice/Exam), посещаемость студента (present/absent/late), оценка (журнал/progressbook)
- **Timetable event** — id, группа, ментор, дата/время, аудитория/филиал
- **Payment** — id, studentId, сумма, валюта (сомони), дата, тип, статус; расходы (Expenses) и должники (Debtors) — рядом
- **Salary / Avans** — id, employeeId, период, начислено, аванс, ставка по уровню
- **Graduate** — id, студент, курс, дата выпуска, место работы (трудоустройство)
- **SmsMailing** — id, аудитория (Group/Students/Leads/Graduates/Mentors), шаблон, текст, статус
- **User** — id, имя, аватар, роль, права; **Role** — id, название, набор прав (экран Administration/Roles); **Log** — запись аудита (Administration/Logs)
- **Branch** — id, название, адрес (филиалы)

Поля, которых нет в макете, не выдумывать. Поля из макета, которых здесь нет, добавить. Каждая сущность — Zod-схема (ТЗ §6).

## 9. Конвенции кода

- Компонент — папка: `Button/Button.tsx`, `Button.module.css`, `index.ts`
- Функциональные компоненты, `React.FC` не использовать, пропсы типизировать явно
- `any` запрещён. Не выводится тип — писать `unknown` и сузить
- Магических чисел и хардкодных цветов в компонентах нет, всё из токенов
- Названия компонентов и пропсов — из макета. Если в Figma компонент называется `StudentCard`, в коде `StudentCard`
- **Деньги — целые числа в дирамах** (1 сомони = 100 дирам), не `float`. Хранение, моки, схемы, расчёты — в дирамах; в сомони переводим только при выводе через хелпер форматирования. Касается Payments, Debtors, Salary, Avans, сумм контрактов и дохода групп
- Один компонент — одна ответственность. Больше 150 строк — повод разбить
- Коммиты по Conventional Commits: `feat:`, `fix:`, `refactor:`

**Доступность — обязательный минимум, не опция:**
- Все интерактивные элементы доступны с клавиатуры, фокус видимый
- Иконочные кнопки имеют `aria-label`
- Контраст текста не ниже 4.5:1. Если в макете ниже — сообщить заказчику, не молчать
- Модалки: ловушка фокуса, закрытие по Esc, возврат фокуса на триггер

## 10. Текст в интерфейсе

Если в макете текста нет — писать по правилам:

- Кнопка называет действие: «Добавить студента», а не «Отправить»
- Действие сохраняет имя на всём пути: кнопка «Сохранить» → уведомление «Сохранено»
- Ошибка объясняет, что случилось и что делать. Без «Что-то пошло не так»
- Пустой экран — приглашение к действию, а не констатация пустоты
- Термины предметные, не системные: «Уведомления», а не «Настройки вебхуков»
- Регистр обычный, без Заглавных Букв В Каждом Слове

## 11. Готовность экрана

Экран считается сделанным, когда:

1. Вёрстка совпадает с макетом — отступы, размеры, цвета, шрифты из токенов
2. Работают все состояния: загрузка, пусто, ошибка, много данных
3. Адаптив от 360 px до 1920 px, поведение по мобильному макету
4. Клавиатурная навигация проходит весь экран
5. Формы валидируются через Zod, ошибки видны рядом с полем
6. `npm run lint` и `npm run typecheck` — без ошибок
7. Тесты на бизнес-логику и на нетривиальные компоненты
