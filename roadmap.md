## Этап 1 — каркас проекта ✅
Vite 6 + React 18 + TS (strict), ESLint 9 + Prettier, Vitest 3. Tailwind с токенами из `tokens.ts` в `tailwind.config.ts` (цвета — через CSS-переменные `globals.css` для темы). Роутер (заглушки по разделам), провайдеры (TanStack Query), структура Feature-Sliced (ТЗ §5). i18n (i18next, rus/taj/eng). Тема light/dark (Zustand + `data-theme`). Хелпер `shared/lib/money` (дирамы, ТЗ §9) с тестами. Скрипты `dev/build/lint/typecheck/test`. Проверки зелёные, дев-сервер и прод-сборка работают.

## Этап 2 — слой данных ✅
Интерфейс `CrmApi` (`shared/api/types.ts`), переключатель `api` по `VITE_API_MODE` (`shared/api/index.ts`), мок-реализация с задержкой 200–600 мс и переключаемой ошибкой (`mockConfig.errorRate`), генерик `queryList` (фильтр→поиск→сортировка→пагинация). Zod-схемы сущностей (Student, Group, Course, Employee, Payment) в `shared/api/schemas` — единственный источник типов; деньги в дирамах. Фикстуры в `src/mocks/fixtures`, валидируются схемами при загрузке. Хуки TanStack Query — в `entities/student` (референс), фабрики ключей — `shared/api/queryKeys`. Заготовка `httpApi` бросает 501. Демо-экран `/students` (список, поиск, loading/error/empty). 18 тестов, все гейты зелёные.

Что осталось для следующих этапов: остальные сущности (Contract, Lesson/Attendance, Timetable, Salary/Avans, Graduate, SmsMailing, Role, Log, Branch) добавляются по мере экранов тем же шаблоном.

### 5.7 Journal (журнал посещаемости) 🟡

Схема `Journal`/`AttendanceStatus` (`shared/api/schemas/journal.ts`), `getJournal` в `CrmApi`, сборка — `shared/api/mock/journal.ts`, хук `entities/journal`.

**Осталось (ждёт макета):** **Progressbook** — оценки по компоненту `Week` из макета (шкала оценок из макета, не выдумываем), экраны Student activity, редактирование отметок. Реализована посещаемость — самое обоснованное на текущих данных.

**Осталось (ждёт макетов):** Expenses (расходы), Debtors (должники), Salary и Avans (аванс) с уровнями ментора (пересекается с Employees/Mentor levels), экраны Accounting/Budget, Accountant. Нужны свои модели (Expense, Debtor, Salary) — по макету, поля не выдумываем.

### 5.9 SMS mailings (рассылки) ✅
Готов экран `/sms`: **композер рассылки** (аудитория — Группа / Студенты / Лиды / Выпускники / Менторы; при выборе группы — её селект), **число получателей считается из реальных данных**, **шаблоны** (вставка текста в сообщение), счётчик символов и SMS-сегментов, отправка (мок создаёт запись), подтверждение/ошибка. Ниже — **история рассылок** (аудитория, получатели, текст, дата, статус), все состояния и пагинация. Три языка.

Аудитории замаплены на существующие данные: студенты — все студенты, группа — студенты группы, **лиды = заявки на обучение** (`signupRequests`, добавлена стартовая фикстура `leads`), выпускники — `graduates`, менторы — сотрудники с должностью mentor. Схема `sms.ts` (`SmsMailing`/`SmsTemplate`/`SendSmsDto`…), методы `getSmsTemplates`/`getSmsMailings`/`getSmsAudienceCount`/`sendSms` в `CrmApi`, сущность `entities/sms` (хуки + `SmsStatusBadge`, отправка через `useMutation` с инвалидацией истории). Фикстуры шаблонов и истории.

### 5.10 Administration (администрирование) 🟡
Готов экран `/administration` с тремя вкладками (`Tabs`):
- **Users** — таблица пользователей (ФИО, телефон, роль-бейдж) из демо-аккаунтов, поиск и фильтр по роли, пагинация, все состояния.
- **Roles** — **матрица «раздел × роль»**, построенная из реального конфига `shared/config/navigation` (единственный источник доступа); read-only с пометкой, что это предложение, а не требование ТЗ. Редактирование — по макету.
- **Logs** — журнал действий (пользователь, действие-бейдж, объект, дата), поиск и фильтр по типу действия, пагинация, все состояния.

Схема `admin.ts` (`UsersQuery`, `LogEntry`/`LogAction`, `LogsQuery`), методы `getUsers`/`getLogs` в `CrmApi`, сущности `entities/user` (`useUsers`, `RoleBadge`) и `entities/log` (`useLogs`, `LogActionBadge`). Пользователи — из `db.accounts`, журнал — фикстура `logs`. Три языка.

**Осталось (ждёт макетов / решений заказчика):** редактирование ролей и прав, экраны **Branches** (филиалы — схема и `getBranches` уже есть, нужен экран) и **Jobs** (вакансии, в макете помечен hidden — брать по подтверждению). Матрицу доступа подтвердить с заказчиком (как отмечено в решениях этапа 5).

### 5.11 Dashboard (дашборд) ✅
Готов экран `/` — собран из готовых данных и компонентов, без новых схем: плитки-счётчики (Студенты / Группы / Сотрудники / Собрано — тоталы из списков + `getPaymentStats`), график **записей по месяцам** (переиспользован `EnrollmentChart` с Enroll), график **дохода по группам** (`GroupIncomeChart` на общем `chartTheme`, суммы в сомони из дирам), список **трудоустроенных выпускников** (`getGraduates` + `EmploymentBadge`). У каждого блока — загрузка/ошибка с повтором. Три языка. Заглушка `PlaceholderPage` с index-роута убрана.

**Осталось (по мере выгрузки макета Dashboard):** полный набор графиков — Leads (линия), Income (пончик %), Attendance (area Late/Absent), Left courses (столбцы), сводка Present/Absent/Late с таблицей. Реализовано ядро на готовых данных; раскладку и остальные графики сверить по макету.
