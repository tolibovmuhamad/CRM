Порядок работ по реальному макету (после этапа 0). Держать в синхроне с ТЗ и `docs/screens.md`: меняется макет/ТЗ — правим роадмеп тем же коммитом. Здесь только порядок и статус, решения — в ТЗ.

## Этап 0 — разбор макета ✅
Токены (`src/styles/tokens.ts`), `docs/screens.md`, `docs/components.md`, ТЗ v1.0. **Дальше — только после подтверждения заказчиком списка экранов и порядка работ.**

## Этап 1 — каркас проекта ✅
Vite 6 + React 18 + TS (strict), ESLint 9 + Prettier, Vitest 3. Tailwind с токенами из `tokens.ts` в `tailwind.config.ts` (цвета — через CSS-переменные `globals.css` для темы). Роутер (заглушки по разделам), провайдеры (TanStack Query), структура Feature-Sliced (ТЗ §5). i18n (i18next, rus/taj/eng). Тема light/dark (Zustand + `data-theme`). Хелпер `shared/lib/money` (дирамы, ТЗ §9) с тестами. Скрипты `dev/build/lint/typecheck/test`. Проверки зелёные, дев-сервер и прод-сборка работают.

## Этап 2 — слой данных ✅
Интерфейс `CrmApi` (`shared/api/types.ts`), переключатель `api` по `VITE_API_MODE` (`shared/api/index.ts`), мок-реализация с задержкой 200–600 мс и переключаемой ошибкой (`mockConfig.errorRate`), генерик `queryList` (фильтр→поиск→сортировка→пагинация). Zod-схемы сущностей (Student, Group, Course, Employee, Payment) в `shared/api/schemas` — единственный источник типов; деньги в дирамах. Фикстуры в `src/mocks/fixtures`, валидируются схемами при загрузке. Хуки TanStack Query — в `entities/student` (референс), фабрики ключей — `shared/api/queryKeys`. Заготовка `httpApi` бросает 501. Демо-экран `/students` (список, поиск, loading/error/empty). 18 тестов, все гейты зелёные.

Что осталось для следующих этапов: остальные сущности (Contract, Lesson/Attendance, Timetable, Salary/Avans, Graduate, SmsMailing, Role, Log, Branch) добавляются по мере экранов тем же шаблоном.

Готово (по UI-Kit, с состояниями и a11y): Button, IconButton, Input, Select, Textarea, Badge (чипы/статусы), Card, Spinner, Modal, Drawer (ловушка фокуса, Esc, возврат фокуса), Tabs, Stepper, DataTable. Иконки — `shared/ui/icons`, утилита `cn`. Theme toggle и Language switcher остаются в `features/` (у них состояние — это корректнее FSD). Тесты: Button, Modal.

## Этап 4 — каркас приложения (`widgets`) ✅

### 5.1 Auth ✅
Экран `/login` и `/signup` (один `AuthPage`, вкладки переключают роут). Вход — телефон + пароль, форма на React Hook Form + Zod, сообщения валидации — ключи i18n на трёх языках. Sign up = **заявка на обучение** (аккаунт не создаётся), после отправки — экран «Заявка принята». «Forgot password?» — модалка с объяснением (экрана восстановления в макете нет).

Слой данных: `login` / `logout` / `getSession` / `signup` в `CrmApi`, схемы в `shared/api/schemas/auth.ts`, сессия мока — в localStorage (`shared/api/mock/sessionStore`), демо-аккаунты — `src/mocks/fixtures/accounts.ts` (вход по телефону, пароль любой). Хуки — `entities/session`.

Роли: `navItemsForRole` / `canAccessPath` в `shared/config/navigation` фильтруют сайдбар и нижнюю навигацию, роуты закрыты `RequireAuth`, недоступный раздел даёт `ForbiddenPage`. **Матрица «роль → раздел» — предложение, а не требование ТЗ: подтвердить с заказчиком при разделе Administration.**

Попутно в `shared/ui`: `Logo` (экспорт из макета), `PasswordInput`, у `Input` — `inputSize`/`rightSlot`, у `Card` — `radius`, у `Button` — размер `xl`, у `Tabs` — `fullWidth`.

### 5.2 Students ✅
Готово: экран списка `/students` в двух видах (таблица и плитка, выбор запоминается), фильтры (поиск с задержкой, курс, группа, контракт), пагинация, удаление с подтверждением, поповер телефонов Student/Father, все четыре состояния (загрузка-скелет, ошибка с повтором, пусто и «ничего не нашли» со сбросом фильтров, много данных). Модель дополнена по макету: `birthDate`, `gender`, развёрнутые `groups` вместо `groupIds`, у группы — `startDate`/`endDate`. В `CrmApi` добавлены `updateStudent` и `deleteStudent`.

Попутно в `shared/ui`: `Popover`, `Pagination`, `SegmentedControl`, `Skeleton`/`TableSkeleton`, у `Select` — `selectSize`, у `Button` — вариант `danger`, у `DataTable` — индекс строки в `render`.

Готовы формы `/students/new` и `/students/:id/edit` (общий `StudentForm`, макеты Add new student / Edit profile). Решения заказчика от 21.07.2026: курса и группы в форме нет — запись в группу идёт через экран **Enroll students**; телефоны — основной плюс список дополнительных с подписями (вместо жёсткого `parentPhone`); статусов три, но руками ставятся только Active/Inactive, Finished система проставляет сама. Из четырёх фреймов «Students/Add new student» канонические — три совпадающих, `14799:47255` («Contract management») считаем черновиком.

Модель по итогам: `firstName`/`lastName` + собираемый бэкендом `fullName`, `phones[]`, `email`, `address`, `telegramUsername`, `branchId`, `notes`, `avatarUrl`. Появилась сущность **Branch** (схема, фикстура, `getBranches`). Фото читается в data-URL и живёт в моках — загрузка на сервер появится вместе с бэкендом.

**Graduates** (`/students/graduates`): счётчики по трудоустройству, поиск по имени и серии сертификата, фильтры (трудоустройство, группа, дата выдачи), таблица с тегами #Work/#OpenToWork/#Freelancer/#FurtherEducation. Файлы сертификатов ждут бэкенда — кнопка выключена с пояснением.

**Enroll students** (`/students/enroll`): столбчатый график записей по месяцам (первый Recharts в проекте), фильтры (поиск, группа, месяц), таблица, выгрузка CSV. Общие настройки графиков — `shared/ui/chart/chartTheme.ts`: цвета через переменные темы, поэтому график живёт и в тёмной теме.

**Мобайл:** на ширине < 640px список студентов всегда плиткой (в макете таблицы на 360px нет), переключатель вида скрыт; вложенные экраны доступны из «Ещё» в нижней навигации. В сайдбаре появились раскрывающиеся разделы (`NavItem.children`) — понадобятся и для Courses, Administration, Accounting.

### 5.3 Groups 🟡
Готов список `/groups` в двух видах (плитка по умолчанию — в макете Groups/Grid идёт первым; таблица на десктопе), плитки-счётчики над списком, фильтры (поиск, филиал, статус, курс), пагинация, все четыре состояния, мобильная версия (на < 640px только плитка).

Модель группы дополнена по макету: `status` (planned/active/finished), `capacity` (счётчик «7/15»), `passingCount` («Passing students»), `scheduleDays` + `lessonTime` + `duration` вместо одной строки `schedule`, `mentorName`. Добавлен `getGroupTags`.

Ряд плиток над списком («Black list, Kettle, Advanced, Handsome, ChatGPT») заказчик 22.07.2026 признал черновыми подписями — плитки убраны вместе со всем слоем `GroupTag` (схема, фикстура, `getGroupTags`, ключ запроса, хук).

**Осталось: карточка группы «C# 5 group»** (студенты, посещаемость, доход) — макет не выгружен.

**Блокер выгрузки (22.07.2026):** Figma REST API отдаёт 429 с `Retry-After: 229764` (~64 ч, до ~25.07) при `x-figma-plan-tier: starter` — это исчерпанная квота тарифа, а не минутный лимит. Токен истекает 27.07, то есть окно по API остаётся ~2 дня. Решение заказчика: **фреймы экспортируются из Figma вручную** в PNG 2x и кладутся в `figma/`.

Нужны фреймы: «C# 5 group» десктоп `4613:26143` (1440×1154), `5669:41313`, `7685:29317`; мобайл `4867:33109`, `4867:34889`, `4867:34295`. Заодно стоит выгрузить десктопные `Groups/Grid` `4892:38362` и `Groups/List` `4892:38391` — их полного дерева в кэше нет, десктопная таблица списка собрана по мобильному макету и логике, её надо сверить.

Роут `/groups/:id` пока не заведён — появится вместе с экраном карточки (сейчас ссылки с плиток и таблицы ведут в 404).

### 5.4 Courses ✅ (сверить по макету, когда откроется Figma)
Готов список `/courses` в двух видах (плитка по умолчанию — в макете Courses/Grid идёт первым; таблица на десктопе, вид запоминается), поиск с задержкой, пагинация, все четыре состояния, мобильная версия (на < 640px только плитка), три языка.

**Собрано по каноническим компонентам UI-Kit, не по догадкам.** Из-за квоты Figma экраны Courses/* выгружены только оболочкой (12–14 узлов, единственный текст — имя в навбаре), но в UI-Kit нашлись сами компоненты:
- `Course` `4929:38592` (343×152) — карточка курса целиком: название 20/28 w600, «Groups: N», кружок курса 56×56, строка «дни занятий · длительность», подвал «Fee: 1000 somoni» (сумма зелёная, w600) и кнопка правки. Отсюда — все поля модели.
- `Syllabus_card` `9809:37355` (343×176) — день силлабуса: заголовок, описание, слот ментора с пустым состоянием «Not have teacher», чипы, edit/delete. **Пока не реализован** — ждёт макета экрана, на котором стоит.
- `chips_course` — Lecture `#4a3aff`, Practice `#ff5700`, Exam `#ef4444`.
- `Logo course` `12293:49556` — набор иконок: C#, C++, Frontend, Python, HTML & CSS, UX/UI.

Модель курса переписана по карточке: `icon`, `groupCount`, `scheduleDays`, `duration`, `fee` (**в дирамах**, ТЗ §9), `studentCount`, `resourceCount`, `tags`. Добавлен `getCourse(id)`.

Попутно вынесено в `shared` (курсам и группам нужно одно и то же, а импорт между сущностями запрещён правилом слоёв): `weekdaySchema`/`Weekday` → `shared/api/schemas/common.ts`, `formatScheduleDays` → `shared/lib/schedule.ts`.

**Ресурсы курса** — `/courses/:id/resources`: шапка с возвратом к списку и названием курса, поиск, фильтр по типу, таблица (иконка типа, имя, тип, размер, дата), все четыре состояния, пагинация. Клик по названию курса в списке ведёт сюда. Сущность `CourseResource` (`courseId`, `name`, `type`, `sizeBytes`, `uploadedAt`), `getCourseResources`, фикстуры, хелпер `shared/lib/fileSize`. Иконки типов (pdf/image/ppt/word/doc/video) перерисованы в общий штриховой стиль по именам наборов из макета (`material-symbols:picture-as-pdf-rounded`, `mdi:file-*`). Загрузка и скачивание файлов выключены с пояснением — ждут бэкенда.

**⚠️ Сверить по макету, когда откроется Figma.** Экраны Courses/* выгружены только оболочкой, поэтому следующее сделано по косвенным данным, а не срисовано:
- **Раскладка Courses/Resources.** Известны шапка, поле поиска и блок контента; состав строки файла (какие колонки, есть ли превью, кто загрузил) — нет. Сделана таблица по аналогии с остальными списками.
- **Фильтры.** У Courses/Grid и Courses/List есть блок `Queries`, содержимое не выгружено. Сейчас на списке курсов только поиск.
- **Колонки Courses/List** выведены из полей карточки (табличный компонент `Frame 8819` — тот же, что в Students/List).
- **Иконки курсов.** В макете `Logo course` — растровые картинки 58×58, вытащить их можно только через API. Пока кружок с коротким кодом курса на подложке из `tokens.chart.categorical`.
- **Маршрут «курс → ресурсы».** Отдельного экрана курса в макете нет, поэтому клик по названию открывает ресурсы.
